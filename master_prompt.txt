Мне нужно превратить текущую папку в полноценное PWA-приложение (Progressive Web App) «Дневник давления и пульса» — МедЖурнал, работающее автономно на iOS (Safari) и Android (Chrome), и организовать код по правильной структуре: файлы логики должны лежать в папке `src/`, а главный файл — в корне.

Пожалуйста, создай и заполни следующие файлы:

1. В корне репозитория: `index.html`
- Это главная точка входа. Подключи сюда Tailwind CSS (через CDN, версия зафиксирована), Lucide-иконки.
- Подключи файлы стилей из `src/styles.css` и логику из `src/app.js`.
- Заголовок должен содержать все необходимые мета-теги для iOS (`apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`), линк на `manifest.json`, `apple-touch-icon`.
- Главный экран: шапка с размытием (ios-blur), карточка «Последнее измерение» (крупные цифры SYS/DIA + категория давления цветным бейджем + пульс + дата), крупная кнопка-CTA с иконкой микрофона «Записать голосом», форма ручного ввода (SYS, DIA, Пульс, Комментарий), история измерений (цветная точка категории, удаление), кнопка «Экспорт в CSV», сноска «данные хранятся только на устройстве».
- Модальное окно голосового ввода: тёмная полноэкранная сцена, крупная пульсирующая иконка микрофона (кольца-анимации), текст статуса «Слушаю… Произнесите показания (например: 120 на 80, пульс 70)», блок ошибок и кнопки «Слушать ещё раз» / «Закрыть».
- Модальное окно проверки показаний (bottom-sheet): редактируемые поля SYS, DIA, Пульс, «Комментарий», блок «Что распознано» с исходной фразой, кнопки «Изменить» / «Сохранить» / «Закрыть без сохранения».

2. В корне репозитория: `manifest.json`
- Полноценный веб-манифест для Android и iOS.
- Укажи `name`: "Медицинский дневник", `short_name`: "МедЖурнал", `start_url`: "./index.html", `scope`: "./", `display`: "standalone", `background_color`: "#f8fafc", `theme_color`: "#f43f5e".
- Добавь массив `icons` с иконками 192x192 и 512x512 maskable-типа (PNG) плюс SVG для общего случая.

3. В папке `src/styles.css`:
- Базовые стили для адаптивного Mobile-First интерфейса в стиле Apple Health (светлая тема, мягкие тени, скруглённые карточки, крупные шрифты), отступы под safe-area.
- Стили для размытия шапки (ios-blur с backdrop-filter), кнопки-CTA, полей ввода (размер шрифта ≥16px, чтобы iOS не зумил), модалок bottom-sheet, тостов, пульсирующего микрофона (кольца через keyframes), состояния ошибки.

4. В папке `src/app.js`:
- Вся интерактивная логика приложения.
- Хранилище данных: `localStorage` (ключ `medjournal.records`) для чтения, записи и удаления замеров (id, date, sys, dia, pul, comment). Дата и время генерируются автоматически при сохранении. Рендер сводки и истории из хранилища.
- Голосовой ввод через Web Speech API (`webkitSpeechRecognition` / `SpeechRecognition`):
  - запуск строго по клику на кнопку «Записать голосом»; настройки: `lang = 'ru-RU'`, `interimResults = false`, `maxAlternatives = 3`;
  - парсер распознанного текста: понимает цифры, в том числе цифровые пробеги внутри склеенных токенов («122x80-75» → 122, 80, 75; пробег длиннее трёх цифр числом не считается), и слова-числительные («сто двадцать» → 120, включая сотни/десятки/единицы); из фразы берутся первые 1–3 числовых значения;
  - назначение строго позиционное, порядок всегда одинаковый: первое число — SYS, второе — DIA, третье — пульс; каждое проверяется на диапазон (SYS 60–260, DIA 30–180, пульс 30–250), значение вне диапазона не заполняется (исправляется на экране проверки);
  - весь текст после последнего распознанного числа — комментарий (первая буква заглавная, лимит 300 символов; если числа не найдены — комментарий пустой);
  - после успешного распознавания автоматически открыть экран проверки с подставленными числами и фразой в блоке «Что распознано»;
  - обработка ошибок с понятными сообщениями на русском: запрещён доступ к микрофону, микрофон не найден, речь не распознана / тишина (с кнопкой «Слушать ещё раз»), нет интернета (распознавание серверное), браузер без поддержки API.
- Валидация при сохранении: SYS 60–260, DIA 30–180, пульс 30–250 или пусто, SYS > DIA; тосты-уведомления об успехе и ошибках.
- Категория давления для сводки и истории: Кризисное (≥160/100), Высокое (≥140/90), Повышенное (≥130/85), Норма (120–129 и <80), Оптимальное.
- Экспорт данных: формирование и скачивание файла `medical_diary.csv` с колонками Дата;SYS;DIA;Пульс;Комментарий (BOM для Excel, разделитель `;`, даты в формате ДД.ММ.ГГГГ ЧЧ:ММ, хронологический порядок).
- Регистрация `sw.js` внутри `src/app.js`.

5. В корне репозитория: `sw.js` (Service Worker)
- Чистый скрипт сервис-воркера для поддержки Offline-first режима: кэширует `index.html`, файлы из `src/`, `manifest.json`, иконки и внешние CDN-ссылки (Tailwind, Lucide), чтобы приложение запускалось и работало без интернета.
- Стратегии: навигации — network-first с фолбэком на кэш; свои файлы — stale-while-revalidate; CDN — cache-first с сохранением при первом успехе; CDN кэшировать мягко (обрыв сети не должен ломать установку); при активации чистить старые кэши.
- Иконки приложения: `icons/icon-192.png`, `icons/icon-512.png` (PNG, маскируемые) и `icons/icon.svg`.

Убедись, что пути к файлам прописаны относительно (например, `./src/app.js`), так как проект будет хоститься на GitHub Pages в подпапке репозитория. Данные пользователя хранятся только локально на устройстве.

Примечание: сам модуль распознавания речи серверный (Chrome/Edge) и требует интернета; история, ручной ввод и экспорт работают офлайн.
